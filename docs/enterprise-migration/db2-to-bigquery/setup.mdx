# Review the DB2 to BigQuery Reference

This path inspects repository artifacts. It does not connect to DB2, write to BigQuery, or execute the configuration.

## Prerequisites

- A checkout of this repository
- A shell with `sed` and `rg`
- No database or cloud credentials

## Run the inspection

From the repository root:

```bash
test -f examples/enterprise-migration/db2-to-bigquery/db2-to-bigquery.yaml
test -f examples/enterprise-migration/db2-to-bigquery/sample-input.json
sed -n '1,80p' examples/enterprise-migration/db2-to-bigquery/sample-input.json
rg -n 'sql_select|mapping|gcp_bigquery' \
  examples/enterprise-migration/db2-to-bigquery/db2-to-bigquery.yaml
```

## Expected output

Both `test` commands exit successfully. The fixture prints a synthetic transaction, and the final command identifies the source, transformation, and destination sections.

## Deployment contract

- Install the IBM Db2 ODBC driver on the selected edge nodes and mount `DB2_CA_CERT` read-only.
- Set `DB2_TLS_PORT` to the database TLS listener, load the database password and `ACCOUNT_HASH_KEY` from the secret manager, and restrict the Db2 role to `SELECT` on `TRANSACTIONS`.
- Use Google Cloud workload identity and grant append access only to the pre-provisioned `financial_data.transactions` table.
- Create that table with a DAY partition on `_partition_date` and schema fields that preserve both `amount` and `currency` before deploying the job.

## Cleanup

No files or external resources are created.

## Common failures

- A missing file means the checkout does not contain the referenced artifact.
- No `rg` matches means the configuration structure changed; inspect the complete file and update the reference before using it.
- Treat syntax inspection as architecture review, not runtime verification.
