# Step 4: Route to Storage

Preserve the table, backup date, and object UUID in message metadata before encoding. The output writes one Snappy-compressed Parquet object per row to the corresponding table and date prefix.

```yaml title="step-4-route.yaml"
pipeline:
  processors:
    - mapping: |
        meta backup_date = this._backup_metadata.backup_date
        meta backup_table = this._table
        meta backup_object_id = uuid_v4()
output:
  processors:
    - mapping: |
        root.table = this._table
        root.backup_type = this._backup_type
        root.backup_date = this._backup_metadata.backup_date
        root.row_checksum = this._checksum
        root.row_json = this.format_json()
    - parquet_encode:
        schema:
          - name: table
            type: UTF8
          - name: backup_type
            type: UTF8
          - name: backup_date
            type: UTF8
          - name: row_checksum
            type: UTF8
          - name: row_json
            type: UTF8
        default_compression: snappy
    - catch:
        - mapping: root = deleted()
  gcp_cloud_storage:
    bucket: ${GCS_BACKUP_BUCKET}
    path: backups/${! metadata("backup_table") }/${! metadata("backup_date") }/${! metadata("backup_object_id") }.parquet
    content_type: application/vnd.apache.parquet
```

The Parquet schema contains `table`, `backup_type`, `backup_date`, `row_checksum`, and `row_json`. The JSON column preserves all source fields and recovery metadata without guessing database column types. Read `row_json` during restore and verify the SHA-256 checksum over the original fields.

Provision the bucket with the required storage class, retention policy, and encryption before deployment. The workload needs object-create permission only; UUID object names avoid overwriting previous rows.

Encoding failures are deleted before storage. Monitor failed processing and test recovery in an isolated database before treating the export as a recoverable backup.
