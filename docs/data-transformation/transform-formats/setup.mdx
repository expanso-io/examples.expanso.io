# Setup Environment for Format Transformation

The canonical pipeline embeds its Avro schema and sends encoded records to Kafka. It does not use Schema Registry or cloud object storage.

## Prerequisites

Provision a Kafka TLS listener, a trusted CA bundle, and SCRAM-SHA-512 credentials. Create `sensor-readings-avro` first and grant the workload identity produce access only to that topic.

## Step 1: Configure Environment Variables

Load the Kafka connection values from the deployment environment and secret manager:

```bash
test -n "$KAFKA_TLS_BROKERS"
test -r "$KAFKA_CA_FILE"
test -n "$KAFKA_USERNAME"
test -n "$KAFKA_PASSWORD"
```

Put port 8080 behind authenticated TLS ingress. Restrict egress to the configured Kafka brokers and mount the CA read-only. Do not use a plaintext 9092 listener.

## Deployment contract

Mount `scripts/examples/sensor_reading.avsc` beside the helper. Kafka receives raw Avro records using this schema; provide the same schema to consumers. The HTTP response honors the request's `Accept` header for JSON, CSV, or XML, while sensor records also retain their Avro Kafka delivery.

Mount `scripts/examples/record_codecs.py` read-only and set `RECORD_CODECS_SCRIPT` to its absolute mounted path. Include `uv` in the workload image; the helper uses only the Python standard library. Configure the output paths on workload-owned persistent volumes, Kafka TLS brokers and SASL credentials where used, and authenticated HTTPS service URLs and tokens.


The authenticated ingress, Kafka TLS listener, SCRAM credentials, topic ACL, and read-only CA mount above are required for deployment.

## Step 2: Review the embedded schema

The schema in `static/files/data-transformation/transform-formats.yaml` is the wire contract. Consumers must use that exact record definition; changing it requires a coordinated compatibility review.
