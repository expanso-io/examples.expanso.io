# Step 3: Session Windows

Unlike fixed time buckets, a **session window** groups events until the configured inactivity period is reached.

The boundary can represent a user interaction period or a sensor activity period when its source semantics support that interpretation.

## Session boundary

An inactivity-based session would group events until a configured gap occurs. It needs explicit state, per-key timeouts, and rules for late or out-of-order events.

The maintained [complete aggregation configuration](/data-transformation/aggregate-time-windows/complete-aggregation-pipeline) implements fixed and sliding windows, not inactivity sessions. `group_by_value` groups an existing batch; it does not maintain per-sensor inactivity timers.

Expanso's `group_by` processor has built-in support for session windows, which simplifies this pattern significantly. You don't need to manage the timeout logic manually.

## Implementation

1.  **Create the Session Pipeline:** Copy the following configuration into a file named `session-windows.yaml`.

    ```yaml title="session-windows.yaml"
    name: session-windows-aggregator
    description: A pipeline that groups sensor data into sessions.
    config:
      input:
        generate:
          interval: if random_int() % 10 > 7 { "6s" } else { "1s" }
          mapping: |
            root = {
              "sensor_id": "sensor-" + (random_int() % 2).string(),
              "activity": "detected",
              "timestamp": now().ts_format_iso8601()
            }
      pipeline:
        processors:
          - group_by:
              - session:
                  timeout: 5s
                processors:
                  - mapping: |
                      let first_event = this[0]
                      let last_event = this[-1]
                      root = {
                        "sensor_id": first_event.sensor_id,
                        "session_start": first_event.timestamp,
                        "session_end": last_event.timestamp,
                        "events_in_session": this.length()
                      }
      output:
        stdout:
          codec: lines
    ```

2.  **Inspect the intended output:** The configuration releases a group after a five-second inactivity gap for the corresponding sensor.

## Verification

The authored session summaries vary in `events_in_session`, `session_start`, and `session_end`. This page does not record an executed result.
