# Troubleshooting

## Quick Diagnosis

```bash
# Check container status
docker ps | grep encrypt-data

# Check recent logs
docker logs encrypt-data --tail 50 2>&1 | grep -i error

# Test encryption endpoint
curl -X POST http://localhost:8080/transactions \
  -H "Content-Type: application/json" \
  -d '{"card_number": "4532123456789010", "email": "test@example.com"}'
```

## Common Issues

### Encryption key errors

**Cause:** Key not set or wrong format

```bash
# A valid AES-256 key is exactly 64 hexadecimal characters
test "${#CARD_ENCRYPTION_KEY_HEX}" -eq 64
printf '%s' "$CARD_ENCRYPTION_KEY_HEX" | grep -Eq '^[0-9a-fA-F]{64}$'
```

**Fix:** Ensure key is proper length and format:

```bash
# Generate a valid 256-bit key encoded as hexadecimal
export CARD_ENCRYPTION_KEY_HEX=$(openssl rand -hex 32)
```

### Fields not being encrypted

**Cause:** Field names don't match config or fields are nested

```bash

docker logs encrypt-data --tail 20 2>&1 | grep -E "(card|email|ssn)"
```

### Decryption fails

**Cause:** Wrong key version or corrupted ciphertext

**Fix:** Store the key version with encrypted data and test the lookup path:

See the [complete configuration](/data-security/encrypt-data/complete-pipeline) for the maintained encryption mapping and its ciphertext fields.

---

### Performance degradation

**Cause:** Encrypting too many fields or large payloads

```bash
docker stats encrypt-data --no-stream
```

**Fix:** Review field selection and measure batching with representative synthetic messages:

```yaml
batching:
  count: 100
  period: 1s
```
