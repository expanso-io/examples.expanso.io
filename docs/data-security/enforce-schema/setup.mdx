# Schema Enforcement Review

The reference pattern evaluates an authored schema and routes records by result. A current machine fixture does not execute the accepted and rejected paths.

<ExampleSurface
  kind="reference"
  title="Before you adapt it"
  description="Resolve the example boundary before changing processors or destinations."
>

- An Expanso environment for configuration inspection
- A versioned schema and representative accepted and rejected records
- Explicit destinations and access rules for rejected data

</ExampleSurface>

## Adaptation checks

- Version schema changes and define compatibility expectations.
- Test missing, extra, malformed, and boundary values.
- Define remediation, retention, replay, and access for rejected records.

## Deployment contract

- Put port 8080 behind authenticated TLS ingress and mount the versioned JSON Schema read-only at `/etc/expanso/schemas/sensor-schema-v1.0.0.json`.
- Set both destination HTTPS origins and load their bearer tokens from the deployment secret manager; restrict each token to ingest-only access.
- Mount `SCHEMA_DLQ_PATH` from persistent storage with retention, encryption, and write permission limited to the Expanso Edge runtime identity.
- Restrict Prometheus access to the monitoring network or an authenticating metrics proxy.

This route is a configuration review, not a verified execution guide.
