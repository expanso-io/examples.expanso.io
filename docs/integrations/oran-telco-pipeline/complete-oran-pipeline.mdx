# O-RAN Telemetry Reference

This checked-in job spec is what `expanso-cli job deploy` sends to Expanso Cloud. It passes `expanso-edge validate`, which checks the config schema, every Bloblang mapping, and the component types. A site-specific exporter or adapter is still required before real DU data reaches it; the built-in simulator runs alongside the real inputs until you remove it as described in the [run path](/integrations/oran-telco-pipeline/setup).

## Deployment manifests

The agent that runs this job is a restricted-SCC Deployment on the SNO node. The full set of manifests, including the AMQ Streams cluster, the OpenTelemetry Collector, the `ServiceMonitor`, and both PersistentVolumeClaims, is in [`examples/integrations/oran-telco-pipeline/openshift`](https://github.com/expanso-io/examples.expanso.io/tree/main/examples/integrations/oran-telco-pipeline/openshift) and applied with `oc apply -k`. ## Adaptation boundary

Review the exporter contract, units, time semantics, thresholds, Parquet schema, Kafka envelope, retention, storage sizing, and credentials before execution. The manifests assume the cluster's default StorageClass and the operator-managed Kafka CA; change both if your SNO node differs.
