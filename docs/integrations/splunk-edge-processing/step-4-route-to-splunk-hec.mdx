# Step 4: Route Retained Events to Splunk HEC

The checked pipeline builds Splunk HEC event objects, sends them over HTTPS,
and writes failed deliveries to a mounted persistent path. The HEC token is
supplied by the deployment secret store and limited to the intended indexes.

## HEC Event Shape

```yaml
pipeline:
  processors:
    - mapping: |
        root = this
        root.splunk_event = {
          "time": now().ts_unix(),
          "host": this.host,
          "source": "expanso:" + this.source_file,
          "sourcetype": this.target_sourcetype,
          "index": this.target_index,
          "event": this.without("splunk_event", "s3_event", "metrics_data")
        }
```

## Authenticated TLS Output

This bounded fragment is the critical-event HEC path from the complete job:

```yaml
output:
  fallback:
    - processors:
        - mapping: root = this.splunk_event
      http_client:
        url: https://${SPLUNK_HOST}:${SPLUNK_PORT}/services/collector/event
        verb: POST
        headers:
          Authorization: Splunk ${HEC_TOKEN}
          Content-Type: application/json
          X-Splunk-Request-Channel: expanso-critical
        tls:
          enabled: true
          root_cas_file: ${SPLUNK_CA_FILE}
        timeout: 30s
        retries: 5
        retry_period: 1s
        max_retry_backoff: 30s
        batching:
          count: 20
          period: 2s
          byte_size: 524288
    - file:
        path: >-
          ${SPLUNK_FALLBACK_PATH}/hec-${! now().ts_format("2006-01-02") }.jsonl
        codec: lines
```

Mount `SPLUNK_CA_FILE` read-only. Mount `SPLUNK_FALLBACK_PATH` from encrypted
persistent storage writable only by the Expanso Edge workload. Size and monitor
the volume, and define replay plus deletion procedures before deployment.

## Validate and Deploy

The checked file is a typed Expanso Edge job:

```bash
expanso-edge validate \
  static/pipelines/splunk-production-pipeline.yaml
expanso-cli --endpoint http://127.0.0.1:19031 \
  job deploy static/pipelines/splunk-production-pipeline.yaml
```

Before deployment, inject `SPLUNK_HOST`, `SPLUNK_PORT`, `HEC_TOKEN`, and
`SPLUNK_CA_FILE` from the deployment environment. Append a uniquely identified
fixture record to one mounted source file, then confirm exactly one indexed HEC
event or one persistent fallback record. Validation alone does not prove HEC
acknowledgement, indexing, or replay.
