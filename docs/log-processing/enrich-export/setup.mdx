# Setup Environment for Log Enrichment

Before deploying the log enrichment pipeline, pre-provision the S3 destinations and KMS key used by the Expanso Edge workload identity.

## Prerequisites

The canonical pipeline generates synthetic records and writes to S3. It does not connect to Kafka and does not read a node-local AWS profile.

## Deployment contract

## Step 1: Configure workload identity

Attach an IAM role to the edge workload. Limit it to `s3:PutObject` on the two configured prefixes and `kms:Encrypt` and `kms:GenerateDataKey` with the selected key. Do not mount long-lived access keys or an AWS profile.

```bash
aws sts get-caller-identity
test -n "$AWS_REGION"
test -n "$S3_BUCKET_NAME"
test -n "$S3_ERROR_BUCKET_NAME"
test -n "$S3_KMS_KEY_ARN"
```

## Step 2: Verify pre-provisioned storage

Enable bucket public-access blocking, require TLS, require the configured KMS key, and set lifecycle and retention policies before deployment. Run the readiness checks below with a provisioning identity authorized for `s3:ListBucket` and `kms:DescribeKey`.

```bash
aws s3api head-bucket --bucket "$S3_BUCKET_NAME"
aws s3api head-bucket --bucket "$S3_ERROR_BUCKET_NAME"
aws kms describe-key --key-id "$S3_KMS_KEY_ARN" >/dev/null
```

## Step 3: Verify Environment Variables

Set environment variables that will be used in the enrichment steps:

```bash
# Set node identification
export NODE_ID="edge-node-demo"

# Set pipeline identification
export PIPELINE_NAME="log-enrichment-s3-demo"

# Verify variables are set
echo "Node ID: $NODE_ID"
echo "Pipeline: $PIPELINE_NAME"
test -n "$AWS_REGION"
```
