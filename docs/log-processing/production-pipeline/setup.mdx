# Setup Environment for Production Log Processing

Before deploying the production log processing pipeline, configure authenticated ingress, Elasticsearch, S3, and alert delivery.

## Prerequisites

The canonical pipeline does not use Kafka, PostgreSQL, or Redis. Put its HTTP listener behind authenticated TLS ingress, attach an AWS workload identity, and restrict egress to Elasticsearch and the alert service.

## Deployment contract

## Step 1: Configure Environment Variables

Load these values from the deployment environment and secret manager:

```bash
test -n "$ELASTICSEARCH_HTTPS_URL"
test -n "$ELASTICSEARCH_API_KEY"
test -n "$S3_BUCKET"
test -n "$S3_KMS_KEY_ARN"
test -n "$ALERT_HTTPS_WEBHOOK_URL"
test -n "$ALERT_API_TOKEN"

case "$ELASTICSEARCH_HTTPS_URL" in https://*) ;; *) exit 1 ;; esac
case "$ALERT_HTTPS_WEBHOOK_URL" in https://*) ;; *) exit 1 ;; esac
```

## Step 2: Verify external access

### Test Elasticsearch Connection

```bash
curl --fail --silent --show-error \
  -H "Authorization: ApiKey $ELASTICSEARCH_API_KEY" \
  "$ELASTICSEARCH_HTTPS_URL/_cluster/health" >/dev/null
```

### Test AWS S3 Access

Run these readiness checks with a provisioning identity authorized for `s3:ListBucket` and `kms:DescribeKey`, rather than the write-only workload role.

```bash
aws sts get-caller-identity
aws s3api head-bucket --bucket "$S3_BUCKET"
aws kms describe-key --key-id "$S3_KMS_KEY_ARN" >/dev/null
```

The workload role needs only `s3:PutObject` on the log prefix and `kms:Encrypt` and `kms:GenerateDataKey` with the configured key. The Elasticsearch API key needs document-create access only to the target log index pattern. The alert token needs send-only access. Do not expose port 8080 without an authenticating proxy or ingress policy.
